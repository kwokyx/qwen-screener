# 方案 B：算法评分 + 千问解读

> 实施日期：2026-05-26  
> 存档对比标签：`archive/pre-algorithm-scoring`（改造前版本）

---

## 1. 方案概述

| 环节 | 是否调用 AI | 负责模块 |
|------|-------------|----------|
| 综合分 `total` | **否** | `score_engine.compute()` |
| 四维子分（估值/盈利/成长/分红） | **否** | 同上 |
| 结论档位 `verdict` | **否** | 由 `total` 阈值映射 |
| 指标明细 `breakdown` | **否** | 分档表逐指标计算 |
| 一句话 `reason`（≤40 字） | **可选** | 千问读 breakdown；失败则用模板 |

**核心原则**：打分有公开、可复现的规则；千问只「读懂分数并说出来」，不改动任何数字。

---

## 2. 请求流程

```
GET /api/v1/qwen/score/{code}?refresh=false
        │
        ▼
  _build_snapshot()  ← StockDaily + StockFinancial
        │
        ▼
  score_engine.compute()  → total / 四维 / verdict / breakdown
        │
        ├─ AI 未配置 → template_reason()
        │
        └─ AI 已配置 → stock_score_reason.md → 千问只返回一句话
              ├─ 成功 → reason_source=qwen（可 Redis 缓存 7 天）
              └─ 失败 → reason_source=template
```

与「问千问」深度分析（`/analysis/{code}/stream`）分工不同：评分区轻量、可缓存；分析区长文、按次调用。  
深度分析 prompt 已注入 `score_verdict`，**综合评级必须与评分卡四档一致**（强烈关注 / 可关注 / 中性 / 谨慎），禁止再使用「推荐」等另一套词汇。

## 3. 评分规则（rule_weighted）

### 3.1 综合分

```
total = 0.30×估值 + 0.30×盈利 + 0.25×成长 + 0.15×分红
```

各子维度均为 0–100 整数。

### 3.2 估值维度（PE 40% + PB 60%）

| PE (TTM) | 得分 | PB | 得分 |
|----------|------|-----|------|
| ≤8 | 95 | ≤1.0 | 95 |
| 8–15 | 80 | 1–2 | 75 |
| 15–25 | 60 | 2–4 | 55 |
| 25–40 | 40 | 4–8 | 35 |
| >40 或 ≤0 | 20 | >8 或 ≤0 | 20 |

缺省项权重按比例分给同维度另一指标；都缺则为 60。

### 3.3 盈利维度（ROE 50% + 毛利率 30% + 负债率 20%）

| ROE(%) | 得分 | 毛利率(%) | 得分 | 负债率(%) | 得分 |
|--------|------|-----------|------|-----------|------|
| >20 | 95 | >40 | 90 | ≤40 | 90 |
| 15–20 | 80 | 30–40 | 75 | 40–60 | 70 |
| 10–15 | 65 | 20–30 | 55 | 60–75 | 50 |
| 5–10 | 45 | <20 | 35 | >75 | 25 |
| <5 | 25 | — | — | — | — |

### 3.4 成长维度（营收同比、净利同比各 50%）

| 同比增速(%) | 得分 |
|-------------|------|
| >30 | 95 |
| 20–30 | 80 |
| 10–20 | 65 |
| 0–10 | 50 |
| -10–0 | 35 |
| <-10 | 20 |

### 3.5 分红维度

| 股息率(%) | 得分 |
|-----------|------|
| ≥5 | 95 |
| 3–5 | 80 |
| 2–3 | 65 |
| 1–2 | 50 |
| 0–1 | 35 |
| 无数据 | 25 |

### 3.6 结论档位（仅由 total 决定）

| total | verdict |
|-------|---------|
| ≥80 | 强烈关注 |
| 60–79 | 可关注 |
| 40–59 | 中性 |
| <40 | 谨慎 |

## 5. API 响应示例

```json
{
  "code": "600519.SH",
  "source": "algorithm",
  "reason_source": "qwen",
  "method": "rule_weighted",
  "cached": true,
  "total": 72,
  "valuation": 58,
  "profit": 88,
  "growth": 62,
  "dividend": 50,
  "verdict": "可关注",
  "reason": "盈利与ROE突出，估值偏高制约总分，股息一般。",
  "breakdown": [
    {"metric": "pe", "label": "市盈率", "value": 28.1, "dimension": "valuation", "score": 60}
  ]
}
```

| 字段 | 含义 |
|------|------|
| `source` | 固定 `algorithm`，表示数字来自规则引擎 |
| `reason_source` | `qwen` / `template` / `none` |
| `cached` | 仅当 `reason` 来自千问且命中缓存时为 true |

## 6. 配置

与改造前相同，在 `backend/.env` 中：

```env
AI_BACKEND=dashscope
DASHSCOPE_API_KEY=sk-...
QWEN_MODEL=qwen-plus
QWEN_SCORE_CACHE_TTL=604800   # reason 缓存秒数，默认 7 天
```

- **未配置 Key**：仍有完整算法分；`reason` 为模板句式。  
- **配置 Key**：算法分立即返回；千问异步生成 reason（首次调 API，之后读缓存）。

---

## 7. 答辩表述建议

1. **量化层**：采用公开分档表与加权公式，结果可复现、可写进论文方法章。  
2. **智能层**：千问阅读算法输出的 breakdown，生成自然语言点评，体现「基于千问」课题特色。  
3. **边界**：评分非交易所官方评级，不构成投资建议；财务为最新一期快照。
