# 条件选股能力差距与扩展方案

更新时间：2026-06-09

## 结论

当前项目不是只有基本面数据，但“条件选股”暴露给用户的字段主要还是基础行情 + 估值 + 财务摘要：

- 已支持：PE、PB、ROE、市值、股息率、营收同比、净利润同比、毛利率、资产负债率、行业、市场、收盘价、换手率。
- 已有数据但未作为通用条件暴露：日线 OHLCV、历史 K 线、内置技术策略使用的均线、突破、成交量、RPS、高位旗形、涨停承接等派生信号。
- 缺数据：新闻情绪、公告事件大类、研报评级、目标价、机构/基金/北向持仓、资金流向、龙虎榜、概念题材热度等。

向同花顺式“条件选股”靠近可以分三层做：

1. 短期可做：把已有日线数据派生出技术面条件，接入条件选股 UI 和 Agent 白名单。
2. 中期可做：补选股范围、ST/上市时长/板块成分、RPS/量比/新高/均线排列等特色指标。
3. 长期较难：消息面、研报、资金面、概念题材热度。难点不在前端，而在稳定数据源、口径统一、版权/授权和增量同步质量。

## 当前能力边界

| 类别 | 当前状态 | 证据 | 说明 |
|---|---|---|---|
| 基本资料 | 部分支持 | `stock_basic` | 股票代码、名称、行业、市场、上市日期、总股本。 |
| 行情估值 | 支持 | `stock_daily` | 日线 OHLCV、PE、PB、市值、换手率、股息率。 |
| 财务摘要 | 支持 | `stock_financial` | ROE、营收、净利、同比、毛利率、负债率；没有扣非、现金流、EPS。 |
| 分红 | 部分支持 | `stock_dividend` | 用于本地计算股息率，不等于完整分红事件筛选器。 |
| 技术面 | 局部具备 | `stock_daily` + `services/strategies/` | 内置策略已算均线、突破、成交量、RPS 等，但通用条件筛选还没暴露这些字段。 |
| 消息面 | 基本缺失 | 无通用表 | 目前只有定增公告策略雏形，不具备新闻/公告/研报通用筛选能力。 |
| 选股范围 | 部分支持 | `market` / `industry` | 可按市场、行业筛选；缺指数成分、ST、上市天数、风险警示、持仓范围等。 |
| 特色指标 | 局部具备 | 内置策略 | 可继续沉淀为字段，例如 RPS、N 日新高、均线多头、放量倍数。 |

## PE 问题的处理口径

PE 数据本身来自行情估值快照，亏损股票会出现负 PE 或空值。之前“PE 低于 15”把负 PE 也算进低估值，这是口径错误，不是上游没数据。

当前修复口径：

- `PE < x`、`PE <= x`、`PE between [a,b]` 自动排除 `PE <= 0`。
- PE 升序排序时，`PE <= 0` 和空值排在有效正 PE 后面。
- 亏损股在前端显示为“亏损”，不再伪装成低估值。

后续如果要更严谨，可以增加 PE 口径字段：

- `pe_dynamic`：动态市盈率。
- `pe_ttm`：TTM 市盈率。
- `pe_static`：静态市盈率。
- `pe_valid`：是否为正且可比较。

## 扩展到技术面条件的方案

难度：中等，建议做。

推荐新增一张最新技术因子表，例如 `stock_technical_factor`：

| 字段 | 说明 |
|---|---|
| `code` / `trade_date` | 股票和交易日 |
| `ma5` / `ma10` / `ma20` / `ma60` | 均线 |
| `volume_ratio_5` / `volume_ratio_20` | 放量倍数 |
| `rps_20` / `rps_60` | 相对强度 |
| `breakout_20` / `breakout_60` | N 日新高突破 |
| `ma_bullish` | 均线多头排列 |
| `drawdown_20` | 近 20 日回撤 |
| `limit_up_recent` | 近期涨停标记 |

操作流程：

1. 后端新增模型和迁移：`stock_technical_factor`，业务唯一键 `(code, trade_date)`。
2. 在同步任务里基于 `stock_daily` 批量计算最新交易日技术因子，不再每次筛选临时滚动全市场。
3. `screener_engine.FIELD_MAP` 增加技术字段，`ALLOWED_FIELDS` 同步增加白名单。
4. `strategy_selector.list_agent_tools()` 给前端返回技术面字段分类。
5. 条件选股 UI 增加字段分组：基本面、技术面、选股范围、特色指标。
6. Agent prompt/schema 增加新字段，但必须保持 unsupported 边界，不支持的消息/资金字段继续拦截。
7. 增加测试：技术字段筛选、排序、空值行为、Agent 不把消息面伪装成技术面。

## 扩展选股范围的方案

难度：低到中等，建议做一部分。

可先支持：

- 市场：主板、创业板、科创板、北交所。
- 行业：已支持下拉选择。
- 上市天数：基于 `stock_basic.list_date`。
- 排除 ST / 退市风险：需要在股票名称或单独字段里维护标记。
- 指数成分：需要新增指数成分同步表，例如沪深 300、中证 500、中证 1000、科创 50、创业板指。

操作流程：

1. `stock_basic` 增加 `is_st`、`list_days` 派生或筛选表达式。
2. 新增 `index_constituent(index_code, code, trade_date)`。
3. 条件 UI 增加“选股范围”分组。
4. Agent 增加表达映射：沪深 300 成分、上市满三年、排除 ST 等。

## 扩展消息面/研报/资金面的方案

难度：较高，不建议在当前收尾阶段强行做。

主要原因：

- 数据源不稳定：免费源常有字段变动、限流、历史缺口。
- 口径难统一：新闻情绪、公告事件、研报评级、目标价、资金净流入都有不同平台口径。
- 合规和版权风险：研报、新闻全文、机构持仓等数据常有授权限制。
- 工程成本高：需要去重、实体匹配、事件分类、增量同步、失败重试、质量监控和 UI 解释。

如果后续要做，建议按事件数据管线推进：

1. 新增 `stock_event` 通用事件表：`code`、`event_date`、`event_type`、`title`、`source`、`score`、`payload`。
2. 先接公告事件，不接新闻全文。
3. 做事件分类白名单：定增、回购、分红、业绩预告、重大合同、减持、增持。
4. Agent 只允许使用已入库事件类型，不允许凭新闻印象筛选。
5. 前端条件页增加“消息面”分组，并在字段能力表标注来源和更新时间。

## 推荐路线

第一阶段：1 到 2 天

- 完成技术因子表。
- 条件页字段分组。
- 支持 8 到 12 个技术面条件：均线、放量、N 日新高、RPS、回撤、涨跌幅区间。
- 文档更新字段能力表。

第二阶段：1 到 2 天

- 增加选股范围：上市天数、排除 ST、指数成分。
- 保存条件策略接入本地/后端持久化。
- 结果页批量加入自选和保存条件策略入口打通。

第三阶段：3 到 7 天以上

- 事件表和公告同步。
- 消息面条件的口径定义、质量监控和 Agent 边界。
- 研报/资金面如果没有稳定授权数据源，建议只写为不支持，不做伪造字段。

## 不建议做的事

- 不要用股票名称、行业或短线涨跌去假装新闻/资金面。
- 不要把 PE 负值当低估值。
- 不要把内置策略命中理由直接暴露成可任意组合的通用字段，除非已经沉淀为可复算的数据表。
- 不要把“同花顺有的标签”先写死到前端，而没有后端数据来源。
