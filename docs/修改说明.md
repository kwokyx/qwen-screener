# 修改说明

> 最近更新：2026-05-26  
> 主题：**因子页 / 对话筛选列表 与 详情页 综合分统一**

---

## 1. 背景与问题

| 现象 | 原因 |
|------|------|
| 因子页「价值分」显示 88，详情页「综合评分」显示 76（如 601288 农业银行） | 两套算法：列表用前端 `bullScore()` 旧公式；详情用后端 `score_engine` |
| 用户误以为列表是「估值分」 | 列名与含义不清；列表实为**综合分**，详情「估值 95」是**子维度** |

旧列表公式（已废弃）：

```
综合分 ≈ 60 + PE 加分(≤20) + 股息率×2(≤15) + ROE(≤15)
```

详情与当前标准公式见 [`股票评分实现方案.md`](./股票评分实现方案.md)（`score_engine` 四维加权）。

---

## 2. 本次改动目标

- **同一股票、同一时刻**：因子页、千问筛选结果页、详情页圆环上的**综合分**一致。  
- 列表**不再**在浏览器里本地算分，统一由后端 `score_engine` 计算。  
- 列表不调千问 API（仅数字分，省费用）；详情页仍可请求千问生成 ≤40 字 `reason`。

## 4. 数据流（改后）

```
筛选 POST /api/v1/screener/screen
    → screener_engine 联表取 PE/PB/ROE/财务等
    → snapshot_from_row + compute_total()
    → 每条 item 带 score_total

详情 GET /api/v1/qwen/score/{code}
    → 同一 snapshot_from_row 字段
    → score_engine.compute() 得 total（与列表 score_total 相同）
    → 可选：千问仅生成 reason 文案
```

## 5. 界面变化

| 位置 | 改前 | 改后 |
|------|------|------|
| 因子页表格列名 | 价值分 | **综合分** |
| 因子页分数来源 | 前端 `bullScore` | 接口字段 **`score_total`** |
| 悬停提示 | 旧 PE/股息/ROE 公式说明 | 与详情一致：`score_engine` 规则评分 |
| 详情页 | 无变化（仍为算法综合分 + 千问解读） | 与列表数字对齐 |

**说明**：详情页「估值 / 盈利 / 成长 / 分红」四条子分仅详情展示，列表只显示**综合分**，二者不必相等（例如估值 95、综合 76 属正常）。

## 6. 部署与验证

```powershell
cd F:\Spring26\StockSystemAcademicDesign\qwen-screener-main
docker compose up -d --build
```

验证步骤：

1. 打开 **因子** 页，应用筛选（如沪深 300 + PE 0–50）。  
2. 记下某只股票（如 601288）的 **综合分**。  
3. 进入 **详情** 页，查看圆环 **综合评分**。  
4. 两处分应一致；列名应为「综合分」而非「价值分」。

若仍为「价值分」或 88/76 不一致，说明容器或浏览器缓存未更新，请强刷（Ctrl+F5）并确认 backend、frontend 均已 rebuild。

## 8. 数据同步：前端误报失败与估值东财失败（2026-05-26）

### 8.1 现象

| 现象 | 原因 |
|------|------|
| 点击「行业 + 财务」立刻弹红色失败，但 `docker logs` 仍在跑 `[INDUSTRY all]` | 接口默认 **async**，返回 `queued: true` 无 `status`；旧前端当成失败 |
| 点击「估值快照」失败，日志 `RemoteDisconnected` | 东财 `stock_zh_a_spot_em` 在 Docker/校园网常被限流；属真实数据源问题 |
| 面板显示「已同步」但估值面很少 | `job_daily_value` 曾吞掉东财异常，pool 部分成功仍标 success |

### 8.2 代码改动

| 文件 | 修改 |
|------|------|
| [`DataFreshness.vue`](../frontend/src/components/DataFreshness.vue) | `queued` 后每 4s 轮询 `/health/data`，显示「同步中」；终态再 toast |
| [`health.js`](../frontend/src/api/health.js) | `triggerSync(job, wait)`；`weekly_basic` 可 `wait=true` |
| [`scheduler.py`](../backend/app/services/scheduler.py) | `job_daily_value` 写 `em_failed` / `partial`；全无数据时 `failed` |
| [`data_sync.py`](../backend/app/services/data_sync.py) | 修复 EM 失败日志 `{}` 占位符 |

### 8.3 东财失败时的备用命令

在宿主机执行（需先 `docker compose up`）：

```bash
docker exec qwen-backend python -m scripts.sync_data pool csi300
docker exec qwen-backend python -m scripts.sync_data pool csi500
```

可补沪深 800 的 PE/PB/股息率，不依赖东财全市场接口。

### 8.4 部署

```powershell
docker compose up -d --build
```

长任务（行业+财务）请等待轮询完成或查看 `docker logs -f qwen-backend`，不要以「刚点开时的红色 toast」为准。
